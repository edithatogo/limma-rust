# LM00 — Fork provenance and Conductor context

## Overview

Establish a source-accurate brownfield context for the actual MassDynamics fork and a bounded plan that can be executed without importing defects from another project.

## Requirements and acceptance

- Record fork, upstream parent, package, licence, exact base and the separate identity of the earlier sinmojito audit.
- Materialise the official Conductor source as a pinned submodule and create the required project context and track registry.
- Record source installation separately from agent-host activation.
- Inspect the current implementation and existing reference harness; describe missing capabilities accurately.
- Correct the unsupported camera capability claim in README and Cargo description without altering scientific code or dependencies.
- Apply the relevant central scientific/native and dependency review standards; retain the supplied general style guide.
- Verify linked context files, JSON and whitespace. Record actual evidence and remaining runtime gates.

## Out of scope

Scientific implementation, dependency installation, corpus regeneration, runner registration, repository settings changes and any qualification claim. Commit/publication is handled by the coordinating change.
